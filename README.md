# Critter

Claude Code 和 Codex 的桌面宠物（a desktop pet for Claude Code and Codex）。

一只常驻在屏幕最上层的小家伙，默认形象是小芽，也可以在设置里换成团子、啾啾、刺球、六六、噗噗、菇菇等其他原创形象。本机每个接入的 Claude Code 或 Codex 会话都对应一只小 Critter，支持终端、VS Code、Claude Desktop 和 Codex Desktop。会话做完了、在等你确认、或者出错了，它都会换个样子、冒出气泡，还可以响一声提示音。点一下 Critter，就能跳回那个会话所在的窗口。

这是一个原生 macOS 应用（Swift），没有任何第三方依赖。它只占大约 20 MB 内存，空闲时几乎不占 CPU。

## 它能做什么

| 状态 | 头顶 | 动作 | 气泡 |
|---|---|---|---|
| 空闲 | 无（睡着后飘出 z） | 变灰、慢慢呼吸，偶尔眨眼、张望、点脚；空闲满 2 分钟就睡着 | 无 |
| 运行中 | 一颗一胀一缩的小太阳 | 按正在用的工具换动作：敲笔记本、思考、读文件、跑命令、抛种子 | 当前在做什么，例如 `Bash: npm test` |
| 等你确认 | 橙色 `?`，右上角常驻一个橙色 `!` | 蹦一下、举手等你；等了 30 秒还没处理就着急地点脚 | 需要你确认的内容 |
| 做完了 | 绿色 `✓`，旁边不时闪一下 | 欢呼开花、撒花瓣，然后开心地待着 | 最后一条回复的第一句 |
| 出错 | 红色 `!` | 变灰，"哎呀"抖一下，然后沮丧地沉下去 | 错误信息 |

每个动作的细节和各种交互见下面的"动画"。

- 每个会话一只 Critter，排成一排。气泡顶部只显示工作目录名，悬停可看完整路径；脚下显示会话名和来源（`cc · 终端 / VS Code / Desktop` 或 `Codex · 终端 / VS Code / Desktop`）。
- 气泡会一直显示，直到该会话的状态再次变化。超长的文字最多显示 2 行，鼠标悬停可以看到全文。
- 会话数超过合并阈值（默认 4）时，所有 Critter 会合并成"一堆"：
  - 最前面那只显示最急的状态，上方显示各状态的数量。
  - 点这一堆可以展开；展开后末尾有"⇥ 收起"把手，点它（或右键菜单里的"收起"）再合并回去。
  - 展开后如果一排放不下（比如会话很多、屏幕较窄），会保持合并，不会有 Critter 跑到屏幕外；这时右键菜单里的"展开"是灰的。
- 会话关闭后，对应的 Critter 会在几秒内自己离开。三种关闭方式都算：`/exit`、直接关掉终端、`kill -9`。
- 如果它没离开，可以右键点它，选"关闭"。
- 透明的地方可以点穿到下面的窗口。整排 Critter 可以拖到任意位置，位置会被记住。
- 显示器拔掉或分辨率变化后，宠物会自动回到屏幕内。

## 动画

所有动作都由形象清单 `Skins/<形象>/manifest.json` 描述，以 60 ms 为一格逐格播放；代码里只有"怎么播放、怎么跳、怎么跟随"这些规则。画面不变的时候时钟不会醒来，只有下一次变化的那一格才会。

### 状态 → 动作

| 状态 | 进入时 | 持续 | 随机小动作 |
|---|---|---|---|
| 空闲 | — | 慢慢呼吸：身体隔几秒软软地压扁一格再弹回来，叶子偶尔晃一晃 | 每 3.6–9.6 秒一次：眨眼、张望、点脚、蹦着散步、打哈欠、打喷嚏、抖叶子、晒太阳……空闲满 2 分钟先打盹，叶子合拢成一个小芽睡着，一呼一吸、每次飘出一个 z |
| 运行中 | 开工（一压扁，掏出笔记本一格格翻开）；头顶一颗一胀一缩的小太阳 | 按 `activity` 换动作，见下表 | 偶尔眨眼 |
| 等你确认 | 眼睛瞪圆、叶子竖起，一压扁弹起来，右上角蹦出橙色 `!`；这个 `!` 一直留到你处理为止 | 举手挥几下、竖着叶子看着你；等了 30 秒改成着急地点脚、挥手，`!` 也蹦得更勤 | — |
| 做完了 | 开花：压扁蓄力跳起，到顶时芽里开出一朵花，撒出花瓣和叶子，落地再小跳一次 | 顶着花笑眯眯，张望；`✓` 旁边隔一会儿闪一下。你点开会话看过之后，花收回芽里 | 眨眼、张望、晃一晃 |
| 出错 | 眼睛变成 × ×、左右抖几下、冒一滴汗，然后叶子蔫下来，飘落一片小叶子 | 低头、垂手、身体沉一格，偶尔叹一口气 | — |

从"运行中"切到别的状态时，如果它正抱着笔记本，会先把笔记本合上收起来，再播新状态的进场。

### 运行中的动作：`activity` 字段

hooks 在状态文件里多写一个可选字段 `activity`，表示会话正在做哪类事（状态文件格式仍是 schema 1，旧文件照常读）：

| 事件 / 工具 | `activity` | 动作 |
|---|---|---|
| 提交提示词；工具调用结束（`PostToolUse`、`PostToolUseFailure`、`PermissionDenied`） | `think` | 思考：望向右上方，两片叶子像螺旋桨一样转起来 |
| Edit / MultiEdit / Write / NotebookEdit，以及其它工具（包括 `mcp__*`） | `laptop` | 抱着笔记本敲代码，敲一阵按一下回车 |
| Read / Grep / Glob / LS / WebFetch / WebSearch | `read` | 读文件：举起放大镜凑到眼前，边看边往旁边挪 |
| Bash / BashOutput / KillShell | `bash` | 跑命令：原地小跑，脚后扬起小灰尘，跑久了冒一滴汗 |
| Agent / Task | `juggle` | 派子任务：抛接三颗种子 |

没有这个字段时按 `laptop`。换动作有防抖：新的 `activity` 要持续 1.2 秒、当前动作至少放了 2.4 秒才换，工具一个接一个快速调用时不会来回闪。

### 交互

- **目光**：指针在宠物附近（约 170 pt 内）时，醒着的空闲 Critter 和做完了的 Critter 眼睛跟着指针往左、右、上、下看；忙着的不分心。
- **注意到你**：指针移到某只身上，它叶子一竖、往上一顶；睡着的会被吵醒。
- **来回蹭**：在同一只身上左右来回晃（1 秒内换向 3 次以上），它会眯眼脸红、冒小爱心；停手 0.7 秒后结束。
- **按下 / 点击**：按下时它眯眼蹲下、扬起灰尘；松开时如果没拖动，它往左看一眼，同时执行原来的点击（跳回会话；点那一堆则展开）。
- **拎起来**：按住拖动超过 3 pt，被按的那只被拎高 3 格、两脚乱蹬，身体比指针慢半拍，往拖动的反方向甩。合并成一堆时只有最前面那只被拎起，后面那一堆整体跟着窗口走。
- **其余的跟着走**：没被抓住的几只先留在原地，再迈小碎步追上来（落后超过 6 格改成小跑，最多落后 12 格；往上拖时跳着跟上，追平那一格落地扬尘），气泡和标签跟着各自的 Critter；追上后转头看着被拎着的那只。
- **放下**：松手后被拎的那只落地扬尘、左右看看；其余的追平后眨眨眼。
- **展开 / 合并**：展开时离那一堆最近的先跳，一只接一只蹦到自己的位置；合并时大家一只只蹦回去，落地就坐进那一堆的后排、变暗垫高，最急的那只站在最前面。
- **加入 / 离开**：新会话的 Critter 像种子发芽一样，先从地里钻出叶子、探出头，再整个蹦出来；会话结束时它挥挥手、钻回地里，噗一下没了，旁边的跳过来补位。
- **显示 / 隐藏**：显示时一只只从地里蹦出来；隐藏时一只只钻回地里。
- 正在跳（展开、合并、补位）或正在加入、离开的 Critter 不理会悬停和按下，拖动时也不跟着走；窗口随时都能拖。

### 减少动态效果

打开"系统设置 › 辅助功能 › 显示 › 减少动态效果"后：每只停在一个代表姿势（睡着的闭眼，出错的下沉一格），头顶标记不动，`!` 直接出现，没有粒子；展开、合并、加入、离开、显示、隐藏都直接到位；拖动时被拎的那只停在一个姿势，其余的不移动。眼睛仍然跟着指针。关掉后立即恢复动画。

## 系统要求

- macOS 14 或更高版本（开发和测试用的是 macOS 27，Apple Silicon）。
- Swift 6 工具链（Xcode 或 Command Line Tools）。
- Claude Code 或 Codex。接入 Claude Code 需要 `claude` 命令在 `PATH` 里；只使用 Codex 时无需安装 Claude Code。

## 安装

```sh
make install
```

安装会做下面几件事，可以重复执行（再跑一次就是升级）：

1. 编译 release 版。
2. 把 `Critter.app` 装进 `~/Applications`，并注册 `critter://` URL scheme。
   - 如果 Critter 正在运行，会自动重启，换成新版本。
3. 把 `critter-hook` 装到 `~/.critter/bin/`。
4. 检测到 `claude` 时，把 `/pet` 装成用户级命令：`~/.claude/commands/pet.md`，并接入状态栏数据。
5. 检测到 `claude` 时，把本仓库添加为本地插件市场（已经添加过就只刷新），并安装或更新 `critter` 插件。插件里是上报状态用的 hooks。
   - 插件按版本号缓存在 `~/.claude/plugins/cache/critter-pet/critter/<版本>/`。改了 `plugin/` 里的 hooks，要同时把 `plugin/.claude-plugin/plugin.json` 和 `.claude-plugin/marketplace.json` 里的版本号加一，重新安装后才会生效。

装完后：

- **已经打开的 Claude Code 会话要重启，才会加载 hooks。** 没重启的会话仍然会出现，但标签上会多一个"·未接入"，状态一直显示为空闲。
- 在任意会话里输入 `/pet`，或者运行 `open ~/Applications/Critter.app`，就能启动 Critter。

### Codex 接入

安装后运行 `open ~/Applications/Critter.app`，会扫描本机 Codex Desktop、Codex CLI 和 VS Code 扩展进程当前打开的日志，后续在日志变动时自动更新，标签分别为 `Codex · Desktop`、`Codex · 终端`、`Codex · VS Code`。Codex 不需要安装 hooks 或修改 `config.toml`，也不提供 Claude Code 的 `/pet` 命令；显示和隐藏可以使用菜单栏、全局快捷键，或运行 `~/.critter/bin/critter-hook toggle`。

Critter 只读 Codex 进程当前打开的 `~/.codex/sessions/**/rollout-*.jsonl`，由文件系统事件触发更新，首次只读元信息和日志末尾，之后增量读取。历史会话不会因文件仍在磁盘上而出现。运行、工具调用、完成、中断和错误会映射到现有动画；日志中出现审批或提问事件时显示“等你确认”。Codex 的外部 `notify` [目前只支持回合完成通知](https://developers.openai.com/codex/config-advanced/#notifications)，因此这里使用本地 rollout，格式变化时可能需要更新适配器。手机连接打开后，还会接入 Desktop / VS Code 现有的本地会话通道；可以向当前会话发消息、回答支持的提问、确认命令或文件权限，并停止指定的运行回合。运行中的消息会追加到当前回合，空闲时启动新回合，沿用该会话的设置。

使用自定义 `CODEX_HOME` 时，需让 Critter 进程也收到同一个环境变量，例如 `CODEX_HOME=/你的/codex目录 ~/Applications/Critter.app/Contents/MacOS/Critter`。由 Finder 启动的应用通常收不到终端里临时设置的变量。

Codex Desktop 的后台进程可能在关闭聊天视图后继续持有日志，此时宠物会保留；可右键“关闭”隐藏到该会话的下一次事件。退出持有会话的 Codex 进程后，对应宠物会清理。`codex exec`、内部任务和子代理不会单独生成宠物。

仅恢复或卸载一个闲置聊天、后台进程持续存活且没有任何日志写入时，变化可能要等下一次日志更新才反映出来；重启 Critter 也会重新扫描。初次读取会向前补齐跨越末尾窗口的完整行（最多额外回溯 4 MiB），超过 4 MiB 的单行会跳过。模型、有效上下文窗口和最新用量会同步到手机，Codex 额度单独显示，不混入 Claude Code 额度。

Codex 会话的气泡会保留最新一条公开进度文字，例如“测试通过，正在更新桌面版”，工具返回或继续思考不会把它覆盖成“思考中”。命令会话在后台继续运行时仍播放跑命令动画，收到对应结束结果后恢复思考；新一轮任务会清空上一轮进度。真实提问、审批、完成或错误会优先显示对应状态。旧 hook 与 Codex 实时记录并存时只展示实时记录，避免重复宠物和错误的等待提示。

### Codex 手机操作的连接与兼容

- 打开设置中的“允许手机连接”，并在 Codex Desktop 或 VS Code 中打开会话。设置里的“Codex 手机操作”显示本地控制通道状态，可点“重新连接”。
- 手机详情按当前会话的能力显示“发一句”“停止当前回合”和审批入口。断开控制通道时退回只读；没有可回答卡片的确认会提示到电脑处理。独立 Codex CLI 只读状态，不会被偷偷恢复到另一个 app-server。
- 命令/文件审批只批准当前请求；原生权限请求仅授予请求中的权限、作用域为当前回合。普通提问保留原始问题 ID；秘密输入、验证、MCP 登录或未识别的请求保留电脑端处理。
- 消息超时或写出后断线时提示“尚未确认”，不会自动重发。审批卡片绑定参数指纹和当前本地代次，旧卡片不会按复用的数字 ID 授权变化后的操作。
- 当前适配使用官方 Desktop / VS Code 客户端现有的 `$CODEX_HOME/ipc/ipc.sock` 协调协议，不启动第二个 app-server，不修改 Codex 设置。它是未公开保证稳定的客户端接口；当前版本校验不通过时禁用操作。已在本机客户端和模拟会话上验证；升级 Codex 后应核对状态栏中的连接状态。

## 卸载

```sh
make uninstall
```

卸载会先把状态栏设置还原成接入前的样子，再移除插件、插件市场、`Critter.app`（并从 Launch Services 注销 `critter://`）、`/pet` 命令、`~/.critter` 和开机自启项（`~/Library/LaunchAgents/local.critter.pet.plist`）。

如果 `~/.critter/bin/critter-hook` 已经不在了（比如 `~/.critter` 被手动删了）而状态栏还包着，卸载会先在仓库里编译一份 `critter-hook`（`swift build -c release --product critter-hook`），用它还原。编译不出来，或者状态栏设置还原不了（比如 `settings.json` 不是合法的 JSON、不是有效的 UTF-8），卸载会在第一步停下来，什么都不删，并打印现在的命令和手动还原的办法；`~/.critter/backup/` 里有 Critter 改动前的备份。改好后再运行一次 `make uninstall`。

**卸载后请重启仍然开着的 Claude Code 会话。** 这些会话启动时已经加载了插件的 hooks，卸载后它们还会继续触发；hooks 发现 `~/.critter/bin/critter-hook` 不在了会直接跳过，不会报错，但要重启会话才会彻底不再调用。

设置保存在 UserDefaults 里，卸载时会保留。要一起清掉，运行 `defaults delete local.critter.pet`。

## 使用

### 显示和隐藏

有三个入口：

- **`/pet`**：设计上终端、VS Code、Desktop 里的 Claude Code 会话都能用；目前只在终端 CLI 里实测过。
  - 它会被 hook 直接拦下，**不会触发模型回复**，你只会看到一行"Critter 已显示"或"Critter 已隐藏"。
  - Critter 没在运行时，`/pet` 会先把它启动起来。
  - Critter 卡死时，`/pet` 会把它强制重启，见下面的"稳定性"。
- **全局快捷键 ⌃⌥C**：可以在设置里改。
- **菜单栏图标**：菜单里有"显示宠物 / 隐藏宠物"、"设置…"和"退出 Critter"。

隐藏只是把窗口收起来。Critter 仍在菜单栏里，会话状态照常记录，但隐藏期间不会响提示音。

### 点击 Critter

- **左键**点 Critter 或它的气泡：跳回该会话的窗口。如果它的状态是"做完了"，同时标记为已看过，变回空闲。
- **右键**：菜单里有"跳回会话"、"关闭"、"隐藏宠物"和"设置…"。

不同来源的会话，跳回的效果不同：

| 会话在哪里 | 点击后 |
|---|---|
| Terminal.app | 前置窗口，并精确选中该会话所在的标签页（通过 AppleScript 按 tty 匹配） |
| iTerm2 | 前置窗口，并选中对应的 session（按 tty 匹配） |
| VS Code、Cursor、Windsurf、Antigravity | 打开该会话所在的工作区窗口 |
| 其它终端，例如 Ghostty、Warp | 激活该应用 |
| Claude Desktop | 激活 Claude.app |
| Codex Desktop | 用 `codex://threads/<id>` 打开对应聊天；打不开时尝试激活宿主应用 |

第一次跳回 Terminal 或 iTerm2 时，macOS 会弹出"自动化"授权，问是否允许 Critter 控制该终端，选"好"即可。

如果当时点了"不允许"，可以到 系统设置 › 隐私与安全性 › 自动化 里重新打开。没打开之前，点击只会激活终端，不会切换到对应的标签页。

### 哪些会话会显示

- 本机所有交互式 Claude Code 会话都会显示。
- 本机 Codex 进程当前持有日志的 Desktop、CLI 和 VS Code 会话也会显示。
- `claude -p` 和 SDK 调用不会显示，这是有意的。
- 云端会话、其它机器上的会话也不会显示。

## 手机连接（Mac 端）

Critter 可以让同一 Wi-Fi 下的安卓手机看到所有会话，并在手机上回答权限请求、提问和计划。这一节只讲 Mac 这一侧；手机应用在 `android/` 里，线上协议见 `docs/critter-bridge-protocol.md`。

### 打开和配对

默认关闭，关着的时候不监听任何端口。

1. 设置 › 手机，打开"允许手机连接"。
2. 点"添加手机…"，弹层里有二维码和 8 位码（4+4 显示），5 分钟内有效，只能用一次。过期后变成"重新生成"；关掉弹层，这个码马上作废。
3. 手机上扫码或输入这个码。弹层（和设置里）会出现一行"「设备名」请求连接"，点"允许"才算配对完成，点"拒绝"则不配对。"允许"不是默认按钮，按回车不会放行。这一行不是模态弹窗，宠物照常可以拖动。没人理会的请求 5 分钟后作废。
4. 配对后设备出现在"已配对的手机"里，显示最后在线时间，每台都可以"撤销"。"重置配对"会忘掉所有手机并换一张新的 TLS 证书，之后要全部重新配对。

没有手机时可以用开发用的命令行客户端代替：`swift run critter-bridge-client pair '<弹层里的 URI>'`，再用 `watch`、`answer` 等子命令收发。

### 状态栏数据

手机上的上下文用量和额度来自 Claude Code 的状态栏。设置里的"状态栏数据"一行显示三种状态：已接入、未接入、已被改成其它类型（`statusLine` 不是 command 类型时不会去改它）。

- 接入的做法：把 `~/.claude/settings.json` 里的 `statusLine.command` 包成下面这样。路径是展开后的绝对路径（`/Users/你` 换成你的家目录），因为单引号里的 `~` 不会展开：

  ```sh
  [ -x '/Users/你/.critter/bin/critter-hook' ] && exec '/Users/你/.critter/bin/critter-hook' statusline -- '<原命令>' || exec /bin/sh -c '<原命令>'
  ```

  包装后原命令照常运行，输出原样不变。万一 `critter-hook` 不在了（比如 `~/.critter` 被删了），`||` 后面那段会直接运行原命令，状态栏不会坏。
- 原来没有状态栏的话，就接成 `[ -x '/Users/你/.critter/bin/critter-hook' ] && exec '/Users/你/.critter/bin/critter-hook' statusline || exit 0`，什么都不输出。实测（Claude Code 2.1.302）终端底部和没有状态栏时一模一样。
- 早先的版本接成的是 `'/Users/你/.critter/bin/critter-hook' statusline -- '<原命令>'`，没有后面那段兜底。这种也认得：撤销时照常还原；重新运行 `make install` 会把它升级成上面的形式。
- 认包装只看格式，不看路径：单引号里的路径以 `/critter-hook` 结尾、后面紧跟 ` statusline` 的（上面两种形式），都算 Critter 的包装。所以路径不一样的包装（比如家目录换过）也认得：`make install` 会换成现在的路径重新包一层，不会套两层；撤销照常还原出原命令。设置里的"已接入"只认现在这个路径的包装。
- 改之前先备份到 `~/.critter/backup/`（备份和原文件权限相同，读不到原权限时是 0600）；除了这一个字符串，文件里的其它字节都不变。`settings.json` 不是有效的 UTF-8 时不做任何改动。
- 撤销：设置里点"撤销"，或者运行 `~/.critter/bin/critter-hook statusline-uninstall`，恢复成原来的命令。`make install` 会自动接入，`make uninstall` 会自动撤销。
- 项目级设置如果覆盖了 `statusLine`，那个项目里的会话采不到这些数据，Critter 不做处理。

### 手机上能做什么

只有四样：

1. 回答**正在等待**的请求：权限（允许 / 拒绝并写理由）、AskUserQuestion 的提问（选项或自由文本；多选题用 `, ` 连接选中的 label）、计划（批准 / 附修改意见退回）。
2. 标记某个会话"已看过"。
3. 往空闲的会话里发一句话。
4. 读形象文件。

电脑和手机谁先答算谁的：

- 在电脑上先答了，手机上的卡片会消失，手机再答也没有效果。
- 在手机上先答了，电脑上的提示框自动关闭。
- 在电脑上按 Esc 拒绝，手机上的卡片也会消失。

这靠新增的 `ask` hook 实现：插件给 `PermissionRequest` 多挂了一项 `critter-hook ask`（超时 600 秒），原来的 `event` 那项保留。`ask` 只有在 Critter 在运行、手机连接已打开、而且 10 分钟内有已配对的手机连过时才会等待，否则立刻返回，终端的行为和没装一样。

目前 `ask` 只对终端里的会话（`CLAUDE_CODE_ENTRYPOINT` 为 `cli`）生效。VS Code、Desktop 和 SDK 里的会话还没验证过确认框能不能和 hook 同时等待，所以 `ask` 在那里直接返回：这些会话照样显示在手机上，但它们的确认只能在电脑上答。插件版本号因此升到 0.3.0。重新运行 `make install` 后，要重启已经打开的会话才会加载它。

### 安全边界

- 手机连接默认关闭，只在打开后才监听端口，而且只接受私有网段的连接。
- 必须配对：用一次性码加用户在 Mac 上确认，TLS 证书固定指纹。设备令牌在 Mac 端只存哈希，可以撤销。
- 手机能做的事只有上面四样，其余一概不能：不能执行命令、不能读文件、不能改设置。
- 回答文件只由 Critter.app 写，目录权限 0700；hook 自己拼决策 JSON，手机传来的内容绝不会原样变成 `updatedInput`。
- 收件箱令牌、TLS 私钥、设备列表，文件权限都是 0600。
- **不防以你本人身份运行的本机进程，包括另一个 Claude 会话。** 这类进程可以写 `~/.critter/answers/`，相当于替你点了"允许"；也可以删 `~/.critter/pending/` 里的文件，让手机上的卡片消失。不防的理由是：能做到这些的进程，本来也能改 `~/.claude/settings.json` 放开所有权限，或者替换 `~/Applications/Critter.app`，所以文件通道没有带来新的口子。

### 已知限制

- 在电脑上允许了一个耗时较长的命令后，手机上的卡片要等命令跑完才会消失。Claude Code 在电脑上点了"允许"时不会通知 hook，Critter 是等到该工具的结束事件（`PostToolUse`）才撤销这个请求。
- 手机用"发一句"发出的消息，在 Claude Code 看来是"另一个会话发来的消息"，它不会把这当作用户的批准。这用的是 Claude Code 没有文档的收件箱接口，Claude Code 升级后可能要重新验证。

## 手机 App（安卓）

安卓版的 Critter（包名 `local.critter.phone`，源码在 `android/`）连到 Mac 上的 Critter，让手机成为第二块屏幕：看所有会话、回答权限请求、提问和计划、往空闲会话里发一句话。Mac 端怎么打开、怎么配对见上一节。手机端需要安卓 10（API 29）以上，不依赖 Google 服务。

### 构建和安装

- 需要 JDK 21 和 Android SDK。第一次运行 `make android-setup`：它写 `android/local.properties`，并在 `~/.android/` 下生成一份发布签名密钥和 `android/keystore.properties`（已有的密钥不会被覆盖，两个文件都不进仓库）。
- `make android` 跑核心库的单元测试，再构建发布版 APK（`android/app/build/outputs/apk/release/app-release.apk`）。
- 手机打开 USB 调试并连上电脑后，`make android-install` 用 adb 安装这个 APK。
- 开发时用调试版：`cd android && ./gradlew :app:installDebug`。调试版多了形象陈列页和几个只在调试时用的接收器，发布版里没有。
- 调试版和发布版的签名密钥不同，不能互相覆盖安装。在两者之间切换前，先运行 `adb uninstall local.critter.phone`；这会删掉手机上的配对，装好后要重新配对。

### 配对

1. Mac 上：设置 › 手机，打开"允许手机连接"，点"添加手机…"。
2. 手机上：打开 Critter，授予相机权限后对准 Mac 上的二维码；扫不上就切到手动输入：从"局域网里的 Mac"里选一台，输入弹层里的 8 位码，核对手机上显示的证书指纹和 Mac 弹层里码下面的"证书指纹"（4 组、每组 4 个字符）一致后，点"信任并配对"。
   - 用 `critter-pair://` 链接打开时，手机总会先弹窗显示 Mac 的名字、地址和证书指纹，确认后才配对；已经配对过时会说明要替换哪台。只接受局域网地址（10/8、172.16/12、192.168/16、169.254/16、100.64/10、本机和 IPv6 链路本地/ULA），其他地址的链接直接忽略。
3. Mac 上点"允许"。手机显示已配对，之后自动连接。
4. Mac 重启、IP 变了不用重新配对：手机按服务名重新找到它，用同一个证书指纹连上。指纹对不上（证书被重置，或者有人冒充）时手机直接显示"需要重新配对"，不会反复重试。
5. 在 Mac 设置里撤销这台手机后，手机同样进入"需要重新配对"。

### 首次引导

第一次打开会依次走：配对、本地网络（只有安卓 17 及以上才有这一步）、通知、悬浮窗、忽略电池优化、保持后台运行。每一步都可以跳过，跳过时会说明少了什么。之后可以在 设置 › 省电 里单独打开"保持后台运行"，或者"重新走一遍引导"。

| 权限 | 用来做什么 | 不给会怎样 |
| --- | --- | --- |
| 本地网络（安卓 17+） | 在局域网里找到并连接 Mac | 找不到 Mac，连不上 |
| 通知 | 常驻通知显示连接状态；有会话等你确认时弹通知，权限请求的通知上直接有"允许""拒绝" | 收不到提醒，只能打开应用看 |
| 悬浮窗（显示在其他应用上层） | 悬浮球，以及让看板能自己打开 | 没有悬浮球，看板不会自动打开 |
| 忽略电池优化 | 熄屏后系统不容易停掉后台连接 | 连接可能被系统停掉 |
| 相机 | 只用来扫配对二维码 | 只能输入 8 位码 |

### 悬浮球和看板

- **悬浮球**：设置 › 悬浮球 › "显示悬浮球"（要先授予悬浮窗权限）。收起时是一小堆小人，最需要你的那只站在最前面；点一下展开所有会话，点某个会话进入详情或作答，可以拖到屏幕两边，会吸边。没有会话时可以选择自动隐藏。
- **看板**：首页的"看板"按钮打开横屏全屏的看板，有两种模式——放大的小人排成一排，或者像仪表盘那样的会话卡片和额度，点右上角的按钮或左右滑切换，会记住上次用的。充电时看板常亮（不充电时和普通界面一样到时间就熄屏），亮度默认 30%，每 3 分钟挪一下画面防烧屏，15 分钟没动静再调暗一档。
- **看板自动打开**：屏幕亮着、充电、手机横着放、而且静止，同时持续 3 秒，看板自己打开；熄屏时从不自己打开，也不会点亮屏幕。拔掉电源 10 秒后（拔电那一刻起就不再常亮），或者手机竖起来 3 秒后，自己退出；平放在桌上或无线充电板上不会退出。在这次充电期间你手动退出过，就不再自动打开，直到下次插电。重力传感器只在充电并且亮屏时才打开。设置 › 看板 › "充电横放时自动打开"可以关掉。
- 自动打开需要悬浮窗权限，vivo、小米等还要打开"后台弹出界面"。系统拦下时（2 秒内看板没出来），这次充电不再尝试，下次插电再试。
- 锁屏时看板可以显示在锁屏上面，但要点"允许"或作答，必须先解锁。
- **减少动态效果**：设置 › 动画。打开后小人停在代表姿势上；系统的"移除动画"打开时也一样。
- **形象**：设置 › 形象。"跟着电脑"（默认）每个会话用 Mac 上选的形象；也可以在手机上单独选五个自带形象之一，所有会话都用它。

### 国产系统要打开的开关

这些系统在熄屏后会把整个应用冻结，连接就断了。**vivo（V2121A，安卓 13）实测：熄屏后日志里出现 `this package has been frozen`。** 要在系统设置里把下面几项都打开（设置 › 保持后台运行 里有每一项的跳转按钮，找不到页面时会退回应用详情）：

- **vivo / iQOO**：自启动；电池里的"后台耗电管理"，设为"允许后台高耗电"；权限管理里的"后台弹出界面"（不开的话看板不能自己打开，失败时没有任何提示）；在最近任务里把 Critter 锁定；如果有"后台冻结"开关，把 Critter 排除在外。
- **小米 / 红米**：自启动；省电策略"无限制"；后台弹出界面；锁定最近任务。
- **OPPO / 一加 / realme**：自启动；允许后台运行；关闭电池优化；锁定最近任务；悬浮窗。
- **华为 / 荣耀**：电池 › 应用启动管理，改为手动管理，三个开关全部打开。
- **三星**：电池设为"不受限制"，加入"永不休眠的应用"。

### 已知限制

- 连接靠一个前台服务保持，熄屏很久之后能不能不被冻结取决于上面的开关；没打开这些开关时，要重新打开应用才会恢复。
- 要在 Wi-Fi 上才会连接（开发时用 `adb reverse` 连 `127.0.0.1` 除外）；Mac 和手机必须在同一个局域网，路由器开了"客户端隔离"就找不到。
- 手机上的所有操作都经过 Mac：Mac 睡眠、Critter 没有运行或关了"允许手机连接"时，手机只能显示最后一次的快照。
- 通知上的"允许"在锁屏时要先解锁。
- 提示音只在看板打开时响，默认关闭，且遵守勿扰模式。
- 悬浮球在一些系统里需要另外允许"后台弹出界面"或"显示悬浮窗"，否则静默失败。
- 看板自动打开依赖重力传感器和充电状态，平放在桌上不算横放；已经打开的看板只有竖起来才退出，平放不退出。

## iOS（开发中）

iPhone 版的 Critter（源码在 `ios/`）还在开发中，现在只能在模拟器里跑，还没有装到真机上。它和安卓版一样连到 Mac 上的 Critter，外观是同一套像素风格，只是少了一些东西。

现在能做的：

- 配对：扫 Mac 上的二维码、打开 `critter-pair://` 链接，或者从局域网里选一台 Mac 再输入 8 位码，流程和安卓版一样。
- 看会话：首页上半是一片草地，每个会话一只宠物站在上面（等你确认的头顶冒橙色气泡，会话多了放不下的合成一堆）；草地跟着时间换天空，离线时天黑、宠物睡着。下面是 5 小时和 7 天两张额度卡和会话列表，等你确认的排在最前。点一行看详情；做完了的会话点开时会告诉 Mac 你看过了。
- 回应会话：在详情里给会话发一句话（Codex 会话要电脑那边接通了控制通道才行），或者停止 Codex 当前这一回合；权限请求直接在首页点"拒绝""允许"，提问和计划点"打开回答"，在卡片里回答。
- 形象：七个内置形象（`Skins/`，和 Mac、安卓是同一份）跟着 Mac 的设置走，也可以在设置里自己挑一个；手机上没有的形象先画小芽，Mac 把清单发来后再换。
- 看板：充电、横放、静止约 3 秒时自动打开（也可以点首页的"看板"按钮），竖起来或拔电后退出。有宠物模式和专业模式，打开时屏幕调到设定的亮度并保持常亮，离开时还原。「看板提示音」默认关闭。
- 减少动态效果：系统的或设置里的任一打开，界面过渡改成淡入淡出，宠物停在代表姿势。
- 只在 App 开着（在前台）的时候连接。退到后台后会等正在送出的回答有了回执再断开；没有推送，也没有后台提醒。

这些只在模拟器里试过。其中几项连模拟器也做不到真的，还没在真机上试过：看板自动打开（模拟器没有充电状态和重力传感器，只能用 `-critterFakeDock` 模拟充电横放）、亮度调节和保持常亮（模拟器不理亮度写入，日志只证明调用对）、系统的“减少动态效果”开关（`simctl` 改不了，只试了 App 自己的开关）、Mac 把清单发来后换掉小芽（只有单元测试）、扫码（模拟器没有相机，只看到了没有相机时的那一页）。模拟器也发不了触摸和键盘，点按、拖动、输入这几条路径只读过代码。待办见 `docs/critter-ios-backlog.md` 的“装到真机的计划”。

在模拟器里跑（需要 Xcode，最低 iOS 17.2，只支持 iPhone）：

```sh
make ios-sim                       # 为模拟器构建，输出在 ios/build
scripts/dev/ios-sim-live.sh        # 模拟器里的 App 连这台 Mac 上真的 Critter
scripts/dev/render-mockups.sh      # 把设计稿 mockups 页面渲染成切片，用来和模拟器截图对照
```

`scripts/dev/ios-sim-live.sh` 的前提和 `scripts/dev/client-live-check.sh` 一样：Critter 在运行，并且 `defaults write local.critter.pet debugEnabled -bool true`。它会构建并安装 App，用一台临时的 `critter-bridge-client` 设备配对，10 秒后截图到 `ios/build/live/home.png`；再把 App 停掉、不带参数重新打开，5 秒后截图到 `ios/build/live/relaunch.png`（`OUT` 环境变量可以改目录）。两张图都应该显示"已连接"和 Mac 上真实的会话，穿着 Mac 分配的形象。脚本全程不会对你的会话发"看过了""发一句""停止"，也不会作答；结束时撤销这台临时设备，Mac 设置里的手机列表中不留痕迹。

`scripts/dev/render-mockups.sh [--dark] [输出目录]` 用无头 Chrome 把设计稿页面（`docs/superpowers/specs/2026-10-19-critter-phone-visual-mockups.html`）渲染成 1400×1500 的切片，默认放在 `ios/build/mockups/`，`--dark` 渲染深色版放在 `ios/build/mockups-dark/`，需要装了 Google Chrome 和带 Pillow 的 python3。

模拟器里的 Debug 构建有一批启动参数（`xcrun simctl launch <模拟器> com.braynlabs.critter -critterFixture home-mixed`），用来直接打开某个画面、某个状态：假数据（`-critterFixture`、`-critterFixtureOffline`）、直接打开某张作答卡、详情、设置或看板（`-critterOpen`、`-critterBoard`）、配对的各个状态（`-critterPairing`）、控件画廊（`-critterGallery`）、模拟充电横放（`-critterFakeDock`），以及帧数和看板的日志。参数和每个假数据的含义都写在 `ios/Critter/Debug/DebugLaunch.swift` 的文件注释里；Release 构建不含这些代码和假数据。

装到真机、推送通知、实时活动（锁屏和灵动岛）和首次引导，都在后面的计划里。iPhone 上没有悬浮球：iOS 不允许 App 画在其他 App 上面，由实时活动代替。

## 调试日志

```sh
touch ~/.critter/debug    # 打开日志，不用重启
rm ~/.critter/debug       # 关闭日志
```

打开后会写两份日志：

- **`~/.critter/app.log`**：Critter 应用的日志。每次显示内容变化记一行（展开或合并、每个会话的状态、窗口位置），还会记下这些事件：
  - 会话退出、被 Esc 打断、被关闭；
  - 跳回窗口的方案和结果（`jump-plan`、`jump-result`）；
  - 提示音播放或跳过的原因（`sound`）；
  - 快捷键注册结果（`hotkey register`）；
  - 展开、合并、加入、离开等编排的开始和结束（`choreo … start` / `choreo … end`）；
  - 指针交互（`pointer notice`、`pointer wake`、`pointer pet`、`pointer petEnd`、`pointer lift`、`pointer drop`）。
- **`~/.critter/hook.log`**：每次 hook 调用记一行，包括事件名和处理结果。

## 稳定性

- **主线程只做界面。** 读写文件、查询进程、执行 AppleScript、播放音效都放在后台队列。
- **卡死兜底。** App 每 2 秒写一次心跳，写到 `~/.critter/app.json`（App 已关闭 App Nap，隐藏时心跳也不会被系统推迟）。如果心跳超过 10 秒没更新，下一次 `/pet` 会先照常把请求发过去，再等最多 1.5 秒：App 回了新心跳，就只是慢了一下，不做处理；没回，才强制结束 Critter 并重新启动它，同时提示"Critter 无响应，已重启"。
  - 强制结束前会核对进程身份：只有可执行文件是 `…/Contents/MacOS/Critter`、而且启动时间和 `app.json` 里记的一致，才算是 Critter。`app.json` 里的进程号可能早已被别的程序占用（例如重启电脑后），这时 `/pet` 只会重新启动 Critter，绝不会结束那个程序。
- **hooks 不依赖 App。** hooks 只负责写状态文件。Critter 没运行或崩溃了，Claude Code 会话照常工作；Critter 再次启动时，会立刻显示每个会话当前的状态。
- **坏数据不会让它崩溃。** 状态文件或 `~/.claude/sessions` 里的文件损坏、格式未知或缺字段时，Critter 会跳过那个文件，其余会话照常显示。

## 开发

```sh
swift build            # 调试版
swift test             # 全部单元测试
make app               # 组装 dist/Critter.app
```

`python3 scripts/dev/make-sounds.py Sounds` 重新合成三套提示音。它需要 numpy，但只在开发时用；生成的文件已经提交，App 本身不依赖它。

两个辅助脚本：

- `scripts/demo-sessions.sh 5`：造 5 个假会话，用来看排版和动画。
  - `scripts/demo-sessions.sh set 1 waiting`：改第 1 个假会话的状态。
  - `scripts/demo-sessions.sh clean`：清掉所有假会话。
- `scripts/measure.sh [--sessions N]`：测量内存（`phys_footprint`）和平均 CPU。加了 `--sessions N` 会先造 N 个假会话，`0` 表示清空。

本机实测（2026-10-17，Apple Silicon，Critter 大小 1.75，除了假会话还有 2 个真实会话）：

| 场景 | 内存 | CPU（`measure.sh`） | CPU（30–60 秒累计） |
|---|---|---|---|
| 7 个会话展开（等你确认、做完了、出错、运行中 ×2、空闲 ×2） | 21 MB | 0.34% | 0.50% |
| 7 个会话展开，其中 6 个在敲笔记本 | 21 MB | 0.46% | 0.57% |
| 7 个会话合并成一堆（同第一行的状态） | 21 MB | 0.07% | — |
| 6 个会话全部空闲、合并，醒着 | 19 MB | 0.04% | 0.10% |
| 同上，全部睡着（一直在飘 z） | 18 MB | 0.10% | 0.23% |

`measure.sh` 的 CPU 是 `ps` 给的衰减平均；"累计"那一列是这段时间里进程用掉的 CPU 时间除以时长，更能反映持续的开销。

目录结构：

| 目录 | 内容 |
|---|---|
| `Sources/CritterCore` | 纯逻辑，全部有单元测试 |
| `Sources/critter-hook` | hook 可执行文件 |
| `Sources/CritterApp` | 菜单栏应用 |
| `plugin/` | Claude Code 插件（hooks） |
| `Skins/` | 形象素材 |
| `Sounds/` | 提示音素材 |

测试用的环境变量（**只用于测试，不要在日常环境里设置**）：

- `CRITTER_HOME`：替换 `~/.critter`；`CLAUDE_CONFIG_DIR`：替换 `~/.claude`。单元测试靠它们把文件写进临时目录。
- 插件 hooks 里写死的是 `$HOME/.critter/bin/critter-hook`，而 `Critter.app` 由 Launch Services 启动，拿不到 shell 里的环境变量，始终读 `~/.critter` 和 `~/.claude`。设了这两个变量，hooks 和 App 就会各看各的目录。
- 所以 `make install` / `make uninstall` 会忽略 `CRITTER_HOME`（并给出提示），始终使用 `~/.critter`；设了 `CLAUDE_CONFIG_DIR` 时也会提示 App 看不到那些会话。
- `CODEX_HOME`：替换 Codex 的默认目录 `~/.codex`。这是 Codex 本身支持的配置；Critter 需使用相同值。

调试开关：

- `defaults write local.critter.pet debugEnabled -bool true` 打开下面几个调试用 URL：
  - `critter://debug-hang`：让主线程卡死，用来测试卡死兜底；
  - `critter://debug-click?target=<会话 id|handle|chips>[&item=<菜单项>]`：模拟点击（或右键菜单里的某一项）；
  - `critter://debug-set`：改设置；`critter://debug-set?debugReduceMotion=1` 模拟打开"减少动态效果"（不动系统设置，`0` 关掉）；
  - `critter://debug-snapshot?path=<绝对路径>.png[&count=N&interval=毫秒]`：把宠物窗口画成 PNG，截屏不可用时用来检查动画；
  - `critter://debug-pointer?x=<屏幕 x>&y=<屏幕 y>`：在那里模拟一次指针移动（目光、悬停、来回蹭），屏幕坐标原点在左下角；
  - `critter://debug-drag?target=<会话 id|chips|handle>&dx=<pt>&dy=<pt>[&steps=N&interval=毫秒&wait=毫秒&hold=毫秒]`：模拟按住、等一会儿、分 N 步拖动、停一会儿再松开。
  - 这些都走真实的鼠标处理代码。发给开发版时用 `open -a dist/Critter.app "critter://…"`，否则会发给 `~/Applications` 里装的那份。
- 在打开 `debugEnabled` 的基础上，再设置 `debugJumpDryRun`，跳回窗口时只记录方案，不实际执行。
- 用完后用 `defaults delete local.critter.pet debugEnabled` 关掉；用过 `debugReduceMotion` 的话，也用 `defaults delete local.critter.pet debugReduceMotion` 删掉。

## 已知限制

- **Claude Desktop：关掉对话后 Critter 不会自动离开。** 实测（2026-10-17）Desktop 的 Code 会话能正常上报状态，来源显示正确，点击能跳回 Claude.app。但在 Desktop 里关掉一个对话并不会结束它背后的 Claude Code 进程，所以收不到会话结束事件。退出 Desktop App，或者右键那只 Critter →「关闭」，它就会离开。
- **VS Code 插件未单独验收。** 终端里的全流程已实测通过：状态流转、提示音、跳回 Terminal 标签页、退出后离开。VS Code 面板内的 `/pet` 与关闭面板后离开，按同一机制视为通过，但没有逐项实测。
- **部分视觉和交互效果还没有逐项验收。** 下面这些在开发时只用日志验证过：
  - 设置窗口（其中的形象列表只离屏渲染检查过排版）；
  - 滑块拖动时的实时缩放；
  - 快捷键实际按下的效果；
  - 跳回 VS Code 窗口；
  - 开机自启是否生效。
- **指针交互只用模拟指针验收过。** 目光、悬停、来回蹭、按下、拖动都用 `debug-pointer` / `debug-drag` 走真实代码路径、逐帧截图核对过，但开发环境里没法移动真实鼠标，也没法截屏，所以没有用真实鼠标逐项试过。
- **"减少动态效果"只用调试开关验证过。** 没有实际切换系统设置；系统设置变化时走的是同一条代码路径。
- **快捷键冲突检测有限。** macOS 没有公开接口能查出其它应用占用了哪些组合键，所以只有在注册失败时，设置页才会显示"该快捷键已被占用"。
- **跳回 iTerm2 的脚本没在本机测试过**，因为本机没装 iTerm2。
- **重装后可能要重新授权。** App 用的是本地 ad-hoc 签名，重新编译安装后，macOS 可能会再次请求"自动化"授权。
- **只支持 macOS。** 状态文件格式和 hooks 与平台无关，以后做 Windows 版只需要重写界面层。

## 自定义形象

所有形象素材都只放在 `Skins/` 目录，每个形象一个子目录。以 `Skins/sprig/manifest.json` 为例，这份数据清单（schema 2）描述了全部形象和动画：像素部件和由它们拼成的姿势、按格写的动作片段、粒子效果、头顶标记、每个状态的进场 / 循环 / 随机小动作和工作动作，以及每种交互用哪个动作。引擎只实现播放、跳跃、跟随这些规则，所以整体替换形象（连同所有动画）不需要改代码。也可以把自定义皮肤放进 `~/.critter/skins/<名字>/`，它会出现在设置的形象列表里；名字和自带的相同时优先用它。清单不完整或有错的皮肤不会出现在列表里，已选中的皮肤出了错会退回小芽。

给皮肤作者：

- 自定义皮肤必须是 schema 2。第一版（schema 1）的自定义皮肤现在一律当作无效，会悄悄退回内置形象。
- 可以写一个 `title`（1–40 个字符），设置的形象列表里显示它，不写就显示目录名。
- 每个状态可以写一组自己的目光姿势 `gaze`（`left` / `right` / `up` / `down` / `center`），目光跟随时就用它们，不写则用 `interactions` 里的 `look*`。小芽它们"做完了"时用它让花一直开着。
- 自带形象的数据都在设计稿里，改完后用 `node scripts/dev/make-skins-from-preview.js docs/superpowers/specs/2026-10-17-sprig-motion-preview.html Skins` 重新生成全部清单。
- 校验比较严格，任何一条不满足，整份皮肤都退回内置：
  - 所有引用（部件、姿势、动作、特效、字形、颜色字符）都必须存在，五个状态齐全；
  - `grid` 必须是 `[18, 10]`，`tickMs` 在 16–1000 之间；
  - 偏移（部件位置、关键格的 dx/dy、常驻 `!` 的 x、`stillDy`）在 ±64 格以内，部件和字形不超过 64×64；
  - 时长和周期在 1–100000 之间（单位是格，转圈标记的 `periodMs` 是毫秒），常驻 `!` 的跳动周期在 1–1000 格之间，随机小动作的权重在 1–1000 之间；
  - 每组粒子最多 64 个，寿命 1–300 格，位置、速度、加速度和摆动都在 ±1000 以内。
