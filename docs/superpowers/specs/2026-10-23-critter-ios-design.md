## 1. 意图

用户平时用的手机是 iPhone【用户定：开发者账号下登记的那台设备就是它】。Android 版能做的，iOS 版也要做：人不在电脑前时看到每个会话的状态，碰到等确认、等回答时直接在手机上处理。

功能照 Android 版【用户定：跳过提问，直接照 Android 版写】。iOS 不允许的那几样，换成系统里最接近的形式（§2）。

iOS 会在 App 退到后台后很快把它挂起，所以 App 在后台时，提醒只能靠 Apple 的推送服务（APNs）送到手机。用户接受推送经过 Apple 的服务器【用户定】。在此之上，推送里的会话内容一律加密，Apple 只能看到密文【Claude 定，比用户接受的"只推概要"更严】。

## 2. 和 Android 版的对应

| Android 版 | iOS 版 | 原因 |
|---|---|---|
| 配对（扫码、手动输入码）、连接协议 | 照搬。扫码可以直接用系统相机，它认得 `critter-pair://` 链接，会打开 App | — |
| 首页、会话详情、发一句、停止当前回合、作答卡片 | 照搬，卡片用 iOS 的底部弹层 | — |
| 悬浮球（浮在其他 App 上） | **实时活动**：灵动岛、锁屏、待机模式（§8.5） | iOS 不允许 App 画在其他 App 上面 |
| 前台服务常连 Mac | 只在 App 开在前台时连接；后台靠 Mac 发推送（§6） | iOS 会挂起后台的 App，连接随之断开 |
| 通知（带「允许」「拒绝」） | APNs 推送的通知，同样带按钮；点按钮时 App 在后台短暂连上 Mac 送回答（§8.7） | 同上 |
| 横放充电时自动打开看板 | App 在前台时照样自动切到看板；App 不在前台时，靠"快捷指令"自动化把它打开，或者让待机模式显示实时活动（§8.6） | iOS 的 App 不能从后台自己打开界面 |
| 各厂商的保活引导 | 不需要；换成"快捷指令"引导（可选） | — |
| 提醒规则（`AlertPlanner`，在手机上算） | 搬到 Mac 上算，规则不变（§6.3） | 手机大部分时间是挂起的 |

## 3. 目标 / 非目标 / 反目标

### 目标（第一版）
1. 和 Mac 上的 Critter 配对后，App 开着时实时显示所有会话，内容和 Android 版一致（Android 设计 §2 目标 1、2）。
2. 作答：权限、提问、批准计划、让它改计划，规则和 Android 版完全相同。电脑和手机谁先答算谁的。
3. 发一句；Codex 会话按能力显示「发一句」「停止当前回合」。
4. 看板：Critter 模式和专业看板。App 在前台时，横放加充电自动切换（§8.6）。
5. 实时活动：在灵动岛、锁屏和待机模式里显示"一堆"小宠物和各状态的数量，App 没开着时也会更新（§8.5）。
6. 提醒：有新的待答请求时，即使 App 没开着、手机锁着，也能收到通知。权限请求可以直接在通知上允许或拒绝（拒绝可以附一句理由）。做完了、出错的通知默认关闭，可以在设置里打开。
7. 小宠物的画面和动画与桌面版逐像素一致：直接复用桌面版的 Swift 代码，不另写一份（§6.1）。

### 非目标（第一版不做）
- 上架 App Store、TestFlight。只用 Xcode 装到用户自己的 iPhone 上。
- iPad 专门排版、Apple Watch、主屏幕小组件。
- 离开局域网后作答。推送在外面也能收到，但作答要和电脑在同一个局域网（和 Android 版一样，不做中转）。
- 局域网推送（Local Push Connectivity）：要另外向 Apple 申请权限，审批要几周，论坛上也有不稳定的反馈【调研】。
- 连接多台电脑。
- 改 Android 版的任何行为。

### 反目标（做出来但这样就算失败）
- Android 设计 §2 的反目标全部继续有效：耗电发热、干扰 Claude Code 会话、局域网里的其他人看到会话内容或替用户点「允许」、用户的状态栏坏掉、点到过期的卡片批准了不该批准的东西。
- **推送里出现明文的会话内容。** 命令、路径、问题、计划、会话名、回复、目录、分支、Mac 的名字，都不能以明文出现在推送里。Apple 能看到的只有密文、随机的请求和会话 id、各状态的数量、形象名和额度百分比。
- **Android 版或桌面版行为变了。** Mac 端只加东西：没登记推送的设备、没配置推送时，Mac 的行为和现在完全一样。
- **刷屏。** 同一个请求只提醒一次；实时活动只在内容真的变了时才更新。

## 4. 约束

- **语言与框架**：原生 Swift 6 + SwiftUI【Claude 定：和桌面版同一种语言，才能直接复用 `CritterCore`】。和桌面版一样不引入任何第三方依赖，只用系统框架（SwiftUI、Network / URLSession、ActivityKit、WidgetKit、UserNotifications、CoreMotion、CryptoKit、VisionKit 或 AVFoundation）。
- **代码位置**：`ios/`，Xcode 工程进仓库【Claude 定】。
- **最低系统**：iOS 17.2【Claude 定：用推送直接启动实时活动（push-to-start）从 17.2 开始】。
- **工具链（本机已有）【调研】**：Xcode 27.1、iOS SDK 27.1，模拟器有 iOS 26.5 和 27.0（iPhone 17 Pro、iPad Pro 11 英寸）。
- **开发者账号【调研】**：付费账号已有，团队 `XB89283VYM`。本机有 Apple Development 和 Apple Distribution 证书，Xcode 管理的描述文件到 2027 年 8 月才过期，团队下登记了 1 台设备。用户的另一个 App `com.braynlabs.wuti` 已经在用推送。
- **Bundle ID**：`com.braynlabs.critter`，App Group `group.com.braynlabs.critter`【Claude 定：沿用用户现有 App 的前缀；放在一个 xcconfig 里，改一处就行】。
- **设备**：用户的 iPhone【用户定】，型号和系统版本还不知道，第一次连上 Mac 时记下来（§13.5）。要在 iPhone 上打开开发者模式，用 USB 或 Wi‑Fi 连上这台 Mac 安装。
- **Mac 要能上网**才能发推送。推送请求走系统网络设置（本机访问 Google 要走代理 `127.0.0.1:1082`，Apple 的推送服务是否要走代理见 §13.6）。
- **iOS 平台事实【调研】**：
  - App 退到后台后很快被挂起，网络连接断开。没有给普通 App 常驻后台连局域网的办法。
  - App 不能画在其他 App 上面。最接近的是实时活动（ActivityKit）：灵动岛（有灵动岛的机型才有）、锁屏、待机模式。实时活动的界面只在数据变化时重画，不能播连续动画。一个实时活动最长活跃 8 小时，之后最多在锁屏上再留 4 小时。
  - App 被挂起时，官方支持的更新实时活动的办法只有推送。iOS 17.2 起可以用推送直接启动实时活动。高优先级更新有系统预算，Info.plist 加 `NSSupportsLiveActivitiesFrequentUpdates` 可以放宽。
  - 推送：免费账号用不了，付费账号可以。用 token 认证：一个 `.p8` 私钥加 Key ID 和 Team ID，签一个 ES256 的 JWT（20 到 60 分钟之间换一次），走 HTTP/2。用 Xcode 装的开发版 App 走 sandbox 环境（`api.sandbox.push.apple.com`）。
  - 通知服务扩展（Notification Service Extension）可以在通知显示之前改它的内容（推送里要带 `mutable-content: 1`），可以用来解密。
  - 通知按钮可以设成要先解锁（`.authenticationRequired`），也可以带一个输入框（`UNTextInputNotificationAction`）。用户点按钮后，系统在后台给 App 一小段时间（约 30 秒）。
  - 后台推送（`content-available`）会被系统限流；用户在多任务里把 App 划掉后就收不到了。
  - 本地网络权限：Info.plist 要有 `NSLocalNetworkUsageDescription` 和 `NSBonjourServices`（`_critter._tcp`）。第一次连局域网时系统会弹窗。
  - `URLSessionWebSocketTask` 默认只收 1 MiB 以内的消息，而协议文档写明快照可能更大，所以必须调大上限（或者改用 Network.framework）。
  - `UIDevice.current.name` 从 iOS 16 起只返回"iPhone"，拿不到用户给手机起的名字。
  - 待机模式（iOS 17）：手机充电、横放、锁着屏时，系统全屏显示小组件和实时活动。
  - App 不能在后台自己把界面打开。"快捷指令"里的个人自动化可以设"充电器已连接 → 打开 App"，并且设成立即运行、不用确认。

## 5. 架构

```
┌──────── Claude Code / Codex 会话 ────────┐
│ hooks、状态栏、Codex 日志（全部已有，不改）│
└──────────────────┬───────────────────────┘
                   ▼
   Critter.app ── Bridge（已有）──── TLS WebSocket，局域网 ────▶ iPhone App（开在前台时）
        │                                                        ▲  点通知按钮时在后台短暂连一下
        └─ PushPlanner + PushSender（新增）── HTTPS/2 ──▶ APNs ──┤
                                                                 ├─▶ 通知（通知服务扩展解密）
                                                                 └─▶ 实时活动（灵动岛、锁屏、待机）
```

- **App 在前台**：和 Android 版一样，长连接收快照，在 App 里作答、发一句。
- **App 在后台或没开着**：Mac 按 Android 版的提醒规则决定要提醒什么，通过 APNs 发通知、更新实时活动。用户点通知上的按钮时，App 在后台连上 Mac 送回答，送完就断开。
- 和 Android 版一样，**文件仍是 hook 和 App 之间唯一的接口**。推送全部在 Critter.app 里完成，hook 不碰网络。

## 6. 电脑端改动

### 6.1 拆出共享代码 `CritterKit`
- 在 `Package.swift` 里新增一个库 target `CritterKit`，平台写 macOS 14 和 iOS 17.2。能在 iOS 上编译、手机要用的代码都移进去：
  - 形象：`Skin.swift`、`SkinRenderer`、`SkinAssigner` 等；
  - 动画：`Motion/` 整个目录、`TickGrid`、`ActorSnapshot`、`FlockModel`、`FlockLayout`；
  - 协议：`BridgeProtocol`、`BridgeSnapshot`、配对 URI 的解析、`AskDecision` 里拼多选答案的规则；
  - 渲染：从 `CritterApp` 移过来的 `SpriteAtlas`（只依赖 CoreGraphics）、`CritterSpriteLayer`（只依赖 QuartzCore）、`MotionClock`（只依赖 Foundation）。
- `CritterCore` 依赖 `CritterKit`，并且 `@_exported import CritterKit`。这样 Mac 端现有的代码和测试一行都不用改，行为也不变。
- 留在 `CritterCore` 的是只有 macOS 才能用的部分：文件监听（FSEvents、kqueue）、进程工具、hook 命令、状态栏安装、Codex 发现和控制通道等。
- 具体哪个文件放哪边由实现者定。验收标准：`swift test` 全部通过；`CritterKit` 能为 iOS 模拟器编译。
- **看板触发逻辑**：把 Android 的 `BoardTrigger.kt` 翻成 Swift 放进 `CritterKit`，`BoardTriggerTest.kt` 一起翻过来。规则不变，只是"系统拦下看板"那条在 iOS 上用不到（§8.6）。

### 6.2 推送登记（协议新增一条消息）
手机连上并通过 `hello` 后，发一条推送登记【Claude 定】。字段的语义如下，具体名字由实现者定，写进协议文档：
- APNs 设备 token（十六进制），环境（`sandbox` / `production`），bundle id；
- 推送密钥：手机生成的 32 字节随机数（base64url），用来加密通知内容（§6.5）；
- 提醒偏好：做完了要不要推、出错要不要推；
- 实时活动：开没开；push-to-start token；当前实时活动的 id 和它的推送 token（有的话）。

规则：
- 每次发都是完整的一份，替换旧的。全部关掉，或者 token 为空，就等于撤销登记。
- Mac 把它存进 `~/.critter/bridge/devices.json` 里这台设备的记录（新增的可选字段，旧文件照常读，文件权限仍是 0600）。
- 在 Mac 上撤销这台设备、点"重置配对"，登记一起删掉。
- Mac 用 `result` 回复。旧版 Mac 不认识这条消息，会直接忽略（协议文档："A frame the Mac cannot decode is ignored once the connection is ready"），手机等不到回复就提示"这台 Mac 上的 Critter 版本太旧，收不到推送"。
- 协议版本号仍是 1。这是可选扩展，Android 版不发也不受影响。

### 6.3 推送决策 `PushPlanner`
纯逻辑，放在 `CritterCore`，有单元测试。输入是前后两份快照（就是发给手机的那份 `SnapshotBody`）和每台设备的提醒偏好，输出是要发的通知、要撤回的通知、实时活动的新内容。规则照搬 Android 的 `AlertPlanner`：
- **新的待答请求**：每个请求发一条"等你确认"通知，只发一次。
- **会话进入"等你确认"，但没有手机能答的请求**（比如 VS Code、Desktop 里的会话，`ask` 只对终端开启；只读的 Codex 会话）：发一条"<名字> 等你确认（请在电脑上处理）"。
- **做完了 / 出错**：设备打开了对应的偏好才发。
- **撤回**：请求了结，或会话离开了那个状态、结束了，就撤回对应的通知（§6.4 的后台推送，尽力而为）。
- **Mac 刚启动、刚打开推送、某台设备刚登记**时的第一份快照只记下现状，不发任何提醒【Claude 定：它描述的是过去；和 Android 版"第一份快照不震动"同理】。
- 手机开在前台时 Mac 照样推，App 自己决定要不要显示横幅（§8.7）。
- 判断随快照的 250 ms 合并一起做，不另开定时器。

### 6.4 推送发送 `PushSender`
- **配置**：在 Mac 设置的"手机"一节里新增"iPhone 推送"：
  - 选择 `.p8` 文件，复制到 `~/.critter/bridge/apns/`（0600）。Key ID 从文件名 `AuthKey_<KeyID>.p8` 读出来，可以改；
  - Team ID；
  - bundle id，默认 `com.braynlabs.critter`。
  - 显示状态：未配置 / 已配置 · 上次发送时间 / 出错原因；
  - 一个"发送测试通知"按钮【Claude 定，方便验证】。
- **签名**：用 CryptoKit 读 `.p8`，签 ES256 的 JWT，缓存约 50 分钟。
- **发送**：URLSession 走 HTTP/2，按设备登记的环境选 sandbox 或正式地址。全部在 bridge 队列上，不碰主线程。
  - 待答请求的通知：`apns-push-type: alert`、`apns-priority: 10`、`apns-collapse-id` = requestId、`apns-expiration` = 请求的 `expiresAt`；
  - 撤回：`apns-push-type: background` 加 `content-available`，带上要撤回的 id；
  - 实时活动：`apns-push-type: liveactivity`，topic 是 `<bundle id>.push-type.liveactivity`。
- **出错**：
  - token 失效（410、`BadDeviceToken`）：删掉这台设备的 token；
  - 密钥或 Team ID 不对（403）：标成配置错误，在设置里显示原因，配置改了之前不再发；
  - 429、5xx、断网：退避重试，最多 3 次，然后记日志放弃。
- **什么时候工作**：手机连接打开、推送配置有效、至少有一台设备登记了推送，三条同时满足才工作。否则什么都不做，没有定时器。
- 现在的 `BridgeController.changed()` 在没有手机连着时直接返回。要改成：有登记了推送的设备时，照样在 250 ms 后组一份快照交给 `PushPlanner`；没有连着的手机就不广播。

### 6.5 通知内容加密【Claude 定】
- 推送密钥由手机生成，经过固定证书的 TLS 连接发给 Mac，和设备令牌一样只存在 Mac 的 `devices.json`（0600）。威胁模型同 Android 设计 §10：本机以用户身份运行的进程不在防范范围内。
- Mac 把通知要显示的 `{标题, 副标题, 正文}` 用 AES-GCM 加密，放进推送里的一个自定义字段。推送里明文的 `aps.alert` 只写"Critter / 有会话需要你"，通知服务扩展解密失败时就显示这句。
- 正文的内容：权限请求是"<名字> 想运行"加命令（或路径）的开头；提问是问题原文；计划是"<名字> 想按计划开工"。副标题是目录 · 分支 · 来源。正文在加密前截短，保证整条推送在 4 KB 以内。
- 明文里只允许出现：请求 id、会话 id（都是随机的）、通知类别、`thread-id`（用会话 id）。
- 实时活动的内容没法加密（系统直接拿去渲染），所以里面不放任何文字（§6.6）。

### 6.6 实时活动（Mac 这边）
- **内容**：各状态的数量；领头那只的形象和状态，后排最多两只的形象和状态；会话总数；5 小时和 7 天额度的百分比；更新时间。没有会话名、目录或任何文字。
- **启动**：手机开着实时活动、Mac 上至少有一个会话、手机上还没有实时活动时，用 push-to-start 启动。App 开在前台时也会自己启动一个（§8.5）。
- **更新**：内容变了才更新。等你确认的数量增加时用高优先级（10），立即发；其它变化用低优先级（5），同一台设备最多每 10 秒一次【Claude 定】。
- **结束**：所有会话结束 5 分钟后结束；手机连接或推送关掉时结束。快到 8 小时上限时（7.5 小时），先结束旧的，再用 push-to-start 开一个新的【Claude 定】。
- **推送 token**：每个实时活动有自己的推送 token，Mac 要拿到它才能更新。App 拿到后通过推送登记（§6.2）交给 Mac。用 push-to-start 启动后，App 能不能在后台拿到 token 并连上 Mac 送过去，见 §13.1。

### 6.7 `critter-hook ask` 的门槛
Android 设计 §6.3 的第 3 条门槛是"最近 10 分钟内有任何一台已配对的手机连过"。iPhone 平时不连着，所以改成：**最近 10 分钟内有手机连过，或者有一台登记了推送、而且推送配置有效的设备。**
- `app.json` 新增一个字段（比如 `pushReachable`），由 Critter.app 写，`ask` 读。
- 实测 1 已经证明 hook 等待时终端的确认框照常同时弹出，所以多等的这些请求对终端没有影响。
- "只对终端会话开启"（`CLAUDE_CODE_ENTRYPOINT == cli`）的限制不变。

### 6.8 Makefile
- `make ios`：用 `xcodebuild` 编译真机版，自动签名（`-allowProvisioningUpdates`）。
- `make ios-install`：用 `xcrun devicectl` 装到连着的 iPhone。
- `make ios-test`：在模拟器上跑 iOS 的单元测试。

## 7. 通信协议
- 不变的：连接流程、配对、`hello`、`answer`、`seen`、`say`、`interrupt`、`skin`、快照、`result`，全部照协议文档。
- `hello.app` 写 `critter-ios/<版本>`。`pair.deviceName` 写 `UIDevice.current.name`（iOS 16 起就是"iPhone"）。

## 8. 手机端

### 8.1 工程与技术栈【Claude 定，实现者可以换等价方案】
- `ios/Critter.xcodeproj`，四个 target：
  - `Critter`：App；
  - `CritterWidgets`：小组件扩展，只放实时活动；
  - `CritterNotify`：通知服务扩展，负责解密；
  - `CritterTests`：单元测试。
- 用 Xcode 的"文件夹同步"分组，新增源文件不用改工程文件。通过本地 Swift 包依赖仓库根目录的 `CritterKit`。
- 界面用 SwiftUI。小宠物用共享的 `CritterSpriteLayer`（CALayer）画，包在一个 UIView 里。
- 网络：`URLSessionWebSocketTask` 或 Network.framework 都行，要求：
  - 固定证书指纹，比对叶证书 DER 的 SHA-256；
  - 收得下大于 1 MiB 的消息；
  - 用 WebSocket ping/pong 做心跳。
- 发现 Mac：`NWBrowser` 找 `_critter._tcp`。
- 扫码：系统相机直接认 `critter-pair://` 链接（App 注册这个 URL scheme）；App 内扫码用 VisionKit 的 `DataScannerViewController` 或 AVFoundation。
- 存储：
  - 钥匙串（和两个扩展共享的 access group）：设备令牌、推送密钥。可访问性用"首次解锁后、仅本机"，因为通知扩展和后台作答都要在锁屏时读到它们；
  - App Group 容器：配对信息（地址、端口、指纹、Mac 名字）、最后一份快照、从 Mac 下载的自定义形象、扩展也要用的设置。
- 内置形象和声音：构建时从仓库根目录的 `Skins/`、`Sounds/` 复制进 App 和小组件扩展，源文件只有一份。
- 字体：Silkscreen 和 Nunito，用 Android 版 `res/font/` 里的同一份文件。像素图标用和 Android 版同一份行数据。

### 8.2 动画与交互
- 动画引擎、形象、渲染全部复用 `CritterKit`，不移植、不重写，所以不需要 Android 那样的金样比对测试。
- 触摸交互同 Android 设计 §8.2：按下 = 注意到你，拖动超过 3 pt = 拎起来，轻点 = boop，来回蹭 = 摸摸，目光跟着手指。
- 减少动态效果：默认跟随系统的"减少动态效果"，设置里也能单独打开，效果同桌面版。
- 时钟用共享的 `MotionClock`，按 `ticksUntilChange` 醒来；App 不在前台、视图看不见时停下。

### 8.3 连接
- **只在 App 开在前台时连接。** 先用上次成功的地址，失败了再用 Bonjour 重新找。
- 断线后在前台退避重连：2 秒起，加倍到 60 秒封顶；网络变化时立刻重连一次。
- 心跳：看板开着时 30 秒一次，其它时候 60 秒一次。
- 退到后台时：正在等回复的作答用后台任务（`beginBackgroundTask`）等完，然后主动断开。
- 离线显示同视觉设计 §8.3：天黑、宠物睡着、"x 分钟前"、作答按钮变灰。
- 每次连上后，如果推送登记的内容和上次 Mac 确认过的不一样（token、密钥、偏好、实时活动的 token），就重发一次。
- **从通知按钮作答**（后台）：连接、`hello`、发 `answer`、等 `result`，整个过程最多 20 秒，然后断开（§8.7）。

### 8.4 首页、详情、作答卡片
- 首页：视觉设计 §8.3（草地、额度卡、会话卡、列表里直接答权限请求）。
- 详情和发一句：视觉设计 §8.5。Codex 会话按 `capabilities` 显示「发一句」「停止当前回合」，同 Android 版。
- 作答卡片：Android 设计 §8.5 和视觉设计 §8.6，用 SwiftUI 的底部弹层。卡片每次都按 requestId 取请求；已在电脑上处理、已过期、失败的提示和 Android 版相同。Codex 的权限请求没有"拒绝并写理由"。
- 从通知打开时，App 直接打开对应的卡片。

### 8.5 实时活动（代替悬浮球）
- **锁屏和横幅**：一小块草地上站着"一堆"小宠物（领头的在前，后两只升高、调暗，同悬浮球收起时的样子），旁边是各状态的数量（状态符号加数字），下面两条 5 小时、7 天额度的小分格条，右下角写更新时间（用系统自带的相对时间文字，比如"3 分钟前"，它会自己走）。
- **灵动岛**：
  - 紧凑：左边是领头那只的代表姿势，右边是最急那个状态的符号和数量；
  - 最小：只有领头那只；
  - 展开：锁屏那一块，加一句"点开查看"。
- **待机模式**：用锁屏那一块的版式，背景纯黑，颜色同视觉设计 §5 里的"看板"。
- 点实时活动打开 App。
- 宠物图片在小组件扩展里用共享的 `SkinRenderer` 画成静态图：内置形象随扩展打包，自定义形象从 App Group 里读。
- 设置里有开关，默认开。关掉时 App 结束当前的实时活动，并通过推送登记告诉 Mac。取消配对时 App 也马上结束它（之后没有 Mac 再推它）；离开一台没能告诉的 Mac 时（§8.8）也结束正在显示的，因为那台 Mac 还拿着它们的推送 token【Claude 定】。
- App 开在前台、有会话、但没有实时活动时，App 自己启动一个，并把它的推送 token 登记给 Mac。
- 太久没更新时（超过 15 分钟，用实时活动的 `staleDate`），界面变灰，写"可能不是最新的"【Claude 定】。会话都还在、只是内容没变时，Mac 大约每 12 分钟补发一次低优先级更新，刷新 `staleDate`，免得内容正确的实时活动变灰【用户定，2026-10-24；这是 §9"只在内容变化时更新"的例外】。

### 8.6 看板
- 两种模式、排版、拖动、防烧屏同视觉设计 §8.7 和 Android 设计 §8.6。横屏，纯黑背景。
- 看板显示时：屏幕常亮（`isIdleTimerDisabled`）；把屏幕亮度设到 0.3（可调），离开看板时还原；15 分钟没人碰、状态也没变时再调暗一档。
- **自动切换（App 在前台时）**：用 §6.1 移植过来的 `BoardTrigger`。充电状态从 `UIDevice` 的电池监控读；横放从 CoreMotion 的重力读，最多 10 Hz，只在充电并且 App 在前台时开。规则不变：横放静止 3 秒打开；拔电 10 秒或竖起来 3 秒退出；这次充电里手动退出过就不再自动打开，到下次插电为止。
- **App 不在前台时**：iOS 不让 App 自己打开。两条路：
  1. 首次引导和设置里教用户建一条快捷指令自动化："充电器已连接 → 打开 App「Critter」"，设成立即运行。App 被打开后，手机一横放就切到看板；
  2. 不做这一步的话，手机充电横放时，待机模式会显示实时活动（§8.5）。
- iOS 的 App 不能显示在锁屏上面，所以没有 Android 那种"锁屏上的看板"，待机模式顶替这个位置。
- 提示音只在看板里响，默认关，同 Android 版。

### 8.7 提醒（手机这边）
- **通知类别**：
  - 权限请求：「允许」「拒绝」「拒绝并写理由…」（带输入框）。三个按钮都要先解锁；
  - Codex 的权限请求：「允许」「拒绝」，没有写理由；
  - 提问、计划：「打开」，进到对应的卡片；
  - 做完了、出错、"请在电脑上处理"：只有正文，点开进 App。
- **通知服务扩展**：用钥匙串里的推送密钥解密，替换标题、副标题和正文；解密失败就保留"有会话需要你"，权限请求这时只给「打开」（进到对应的卡片），不给「允许」「拒绝」：用户看不到要批准的是什么【Claude 定，2026-10-24】。扩展没运行、来不及解完时也一样：Mac 推送里的类别本来就是只能打开的那个，真正的类别只在自定义键 `k` 里，扩展解开文字后才换过去（计划 5）。
- **点按钮作答**：App 在后台按 §8.3 连上 Mac 送回答，然后用同一个通知 id 换一条结果通知：
  - 成功："已允许" / "已拒绝"；
  - Mac 说已经了结：同 Android 版的"已在电脑上处理"、"已经过期了"；
  - 送不到："没送到：连不上 Mac（要和电脑在同一个 Wi‑Fi）"。这时保留原来的按钮，可以再点一次。
- **App 开在前台时**：快照里已经有的请求不显示横幅，只轻震一下（触感反馈）；其它的照常显示横幅。
- **撤回**：收到 Mac 的撤回推送时，删掉对应的通知。后台推送不保证送达，所以 App 每次回到前台时，也把快照里已经没有的请求的通知删掉。过期卡片上的按钮是安全的：Mac 会回"已在电脑上处理"。
- 等你确认的通知用"时效性通知"级别（`time-sensitive`），能在专注模式里按用户的设置提醒；做完了、出错用普通级别。
- 遵守系统的专注模式和"显示预览"设置（系统默认是解锁后才显示内容）。

### 8.8 首次引导与设置
- **首次引导**：欢迎 → 配对（扫码或手动输入码；本地网络的系统弹窗在第一次连接时出现）→ 通知权限 → 实时活动说明 → 看板自动打开（可选，快捷指令的图解步骤）。
  - 种子进度 `n / 4`（欢迎页不算，和 Android、视觉设计 §8.2 一样）。
  - 每一步都能跳过，并说清楚跳过的后果。
- **设置**分组：
  - 连接：已配对的 Mac、状态、重新配对、取消配对（取消前先尽量告诉 Mac 撤销推送登记）。告诉不了时（连不上、3 秒没回、拒绝），手机换掉推送密钥、结束实时活动，并在设置和配对页提示去那台 Mac 上撤销这台手机（它还可能发来通知和实时活动）；没连上时取消配对的对话框先说清楚。Mac 已经不认这台手机时（`denied badToken`：它撤销了这台手机或重置了配对，登记一起删了）什么也不说【Claude 定】；
  - 推送：Mac 是否配置好了推送、本机是否登记成功、"发一条测试通知"；
  - 实时活动：开关；
  - 看板：自动横屏切换、默认模式、亮度；
  - 提醒：做完了、出错；
  - 形象：跟着电脑，或者手机上单独选；
  - 动画：减少动态效果。

### 8.9 视觉
- 全部按视觉设计 §4–§7 和草图：像素材质、颜色、字体、动效节拍。dp 按 1:1 换成 pt。
- 排版基准用 iPhone 17 Pro 模拟器（402×874 pt）【Claude 定】。
- 应用图标：用 Android 版小芽图标的同一套画面，做成 1024 px 的单张图，加深色和着色两个变体。启动画面：清晨天空色加居中的图标。
- 弹层、导航遵守 iOS 的习惯：下拉关闭弹层，左边缘右滑返回。

## 9. 省电要求
Android 设计 §9 的要求逐条换成 iOS 的说法，代码审查时逐条检查，不做耗电实测【沿用 Android 版的用户决定】：
- 只在画面变化时才画：宠物时钟按 `ticksUntilChange` 醒来；所有会话空闲时不重画；App 不在前台、视图看不见时停掉时钟。
- 动画最快每 60 ms 一帧；不用 `CADisplayLink` 常驻、不用无限循环的 SwiftUI 动画；时钟文字每分钟只刷新一次。
- 网络：只在前台连接；服务器主动推送，不轮询；断线指数退避；Bonjour 只在连接失败时找。
- 传感器：只在充电、App 在前台、开着自动切换时读重力，最多 10 Hz，拔电立刻停。
- 屏幕：看板纯黑、默认亮度 0.3、没人碰时再暗一档；常亮只在看板显示时开，离开就关。
- 后台：不用后台刷新、不用后台定位、不用静音音频保活这类办法。
- 实时活动：只在内容变化时更新，低优先级的每台设备每 10 秒最多一次；例外是会话都在但内容不变时，约每 12 分钟一次低优先级的刷新（§8.5）。
- Mac 端：没配置推送或没有设备登记时什么都不做；推送只在快照变化时判断。不能改变桌面版现有的内存和 CPU 表现。

## 10. 安全
Android 设计 §10 全部继续有效。另外：
- 推送内容端到端加密（§6.5）。Apple 只看得到密文、随机 id、各状态数量、形象名和额度百分比。
- `.p8` 密钥只放在 Mac 的 `~/.critter/bridge/apns/`（0600），不进仓库，不离开这台 Mac。
- 通知上的作答按钮都要先解锁。
- 手机上的设备令牌和推送密钥放钥匙串，不放 App Group 文件。
- 手机能做的事仍然只有 Android 设计 §10 的四样，加上登记推送。
- 取消配对：手机先尽量撤销推送登记；App 被删掉后，Mac 收到 410 就删掉 token；在 Mac 上撤销设备也会删掉登记。

## 11. 稳定性与失败方式
- Mac 没网、推送配置错了：App 开着时照常用，Mac 设置里显示原因。hook 和桌面版不受影响。
- 手机不在局域网：通知和实时活动照样能收到；作答提示"连不上 Mac"；App 显示离线。
- App 被挂起或被划掉：对 Mac 没有影响，待答请求照旧 590 秒超时。
- 通知服务扩展解密失败（首次解锁前读不到密钥、密钥换过、推送坏了）：显示通用文字；权限请求只给「打开」，进 App 里的卡片看清楚再答，不能在通知上直接允许一条看不到的命令【Claude 定，2026-10-24，原来是"按钮照常能用"】。
- 实时活动的推送 token 没送到 Mac：实时活动停在旧内容，15 分钟后变灰（§8.5）。
- 坏的快照、坏的形象文件直接跳过，不能崩溃；坏的自定义形象退回内置的小芽。

## 13. 待实测 / 风险（实现早期先验证）
1. **实时活动的推送 token 能不能送回 Mac。** 用 push-to-start 启动的实时活动，系统会在后台唤醒 App 让它拿 token；要验证 App 在那段时间里能不能连上 Mac 把 token 登记过去。不行的话改用 iOS 18 的广播频道推送（channel），或者只让 App 在前台时启动实时活动。
2. 实时活动的更新预算：每 10 秒一次的低优先级更新会不会被系统压住。
3. 从通知按钮作答的耗时：连接、`hello`、`answer`、`result` 能不能在系统给的后台时间里完成。Android 上送不到时约 8–9.5 秒给出提示。
4. 时效性通知在专注模式下的实际表现。
5. 用户 iPhone 的型号和系统版本（有没有灵动岛，是不是 iOS 17.2 以上）。
6. 这台 Mac 访问 `api.sandbox.push.apple.com` 要不要走代理。
7. APNs 密钥：用户的另一个 App 已经在用推送，可能已经有 `.p8`；没有的话，要用户在开发者网站新建一个，下载下来交给 Mac 的设置（`.p8` 只能下载一次）。

## 14. 建议的实现顺序（交给实现计划细化）
1. **拆出 `CritterKit`**：Mac 行为不变，测试全过；把 `BoardTrigger` 移植成 Swift。
2. **iOS 骨架**：Xcode 工程、配对、连接、首页（先只用文字）、作答卡片、详情和发一句。只在前台工作，用模拟器连真的 Mac 验证。
3. **宠物与看板**：`CritterSpriteLayer` 接进 SwiftUI、首页草地、看板两种模式、自动切换，按视觉设计做完整的界面。
4. **Mac 推送**：推送登记、`PushPlanner`、`PushSender`、加密、`ask` 门槛、设置界面、测试通知。
5. **iOS 推送**：通知服务扩展、通知按钮后台作答、实时活动（小组件扩展、push-to-start、token 登记）、首次引导、设置。
6. **收尾**：真机检查点、README、Makefile、协议文档。
