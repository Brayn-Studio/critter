## 1. 意图

用户在真机走查后的评价是：手机 App 的界面“非常丑陋，没什么美感，和 Critter 宠物本身可爱的画风丝毫不搭配”。这一轮**从零开始只做视觉**【用户定】，范围包括 `docs/critter-phone-backlog.md` 里剩下的条目、UI/UX 设计和动画效果【用户定】，目标是“尽可能美观”【用户定】。

现状的问题，归结起来是三条：

1. **宠物不在界面里。** 首页、专业看板、作答卡片全是 Material 默认卡片加圆点，宠物只出现在悬浮球和宠物看板。
2. **两种画风打架。** 宠物是 18×10 的像素画，界面是平滑圆角、系统字体、系统图标，放在一起像贴纸。
3. **主色是 Claude 的品牌色。** `CritterOrange = #D97757`。改名成 Critter 就是为了和 Claude 分开（见改名约定），App 的主色不该再用它。

## 2. 目标 / 非目标 / 反目标

### 目标
1. **一套像素材质**，所有界面部件都按宠物身体的画法做（§4）。宠物站在界面里像同一个世界里的东西。
2. **宠物回到每个界面**：首页草地、会话卡片小头像、作答卡片、详情弹层、专业看板卡片、通知大图标、引导插图、设置里的形象选择。
3. 台账第一部分三项：应用图标、看板打开时藏起悬浮球、看板里拖动宠物后走回原位。
4. 台账第三部分里跟画面有关的条目（§9）。
5. 动效有统一的节拍和规矩（§7），每个动作都有头有尾。
6. 浅色、深色都做完整；看板保持纯黑。

### 非目标
- 改宠物形象本身或动画引擎的行为（`:core` 的动作逻辑、清单格式不动）。
- 改协议、连接、作答的逻辑。台账里的逻辑问题另起一批修（§9 末尾）。
- iOS、平板专门排版。

### 反目标
- **耗电变多。** 原设计 §9 的省电要求全部继续有效：不加任何无限循环的界面动画；持续在动的只有宠物，宠物仍然只在画面变化时重画；列表里的小头像是静止的；看板仍然纯黑、低亮度。
- **像 Claude / Claude Code。** App 主色、图标、Logo 不用 #D97757、不用 ✻ 符号、不用 Clawd 形象。Clawd 仍然是默认形象，只在“它自己”出现的地方出现。
- **复古到难用。** 像素感只在边角、图标、数字上；正文用平滑的字体，字号和对比度照常（正文 ≥ 4.5:1，触控目标 ≥ 44dp）。
- **数字认不出。** 小字号下 2 和 8 必须分得清（草图第一版用 Pixelify Sans 就栽在这里，已换掉）。

## 3. 约束

- 设备基准：vivo V2121A，1080×2400 @480dpi，即 360×800dp。草图的手机框就是 360×800。
- 不能依赖 Google Play 服务：字体随 App 打包，不用可下载字体。
- 中文字体不打包（几 MB，且会话名、命令里什么字都可能有），跟随系统【Claude 定】。
- 宠物绘制继续用 `CritterView`（自定义 View + Canvas），界面用 Compose。悬浮球窗口是 View。
- 系统通知的外观由系统决定，能改的只有小图标、颜色、大图标、文字、按钮。

## 4. 像素材质【Claude 定】

宠物身体的三个特征，所有部件照着做：

| 特征 | 宠物上 | 部件上 |
|---|---|---|
| 台阶圆角 | 身体轮廓 `..BBBB..` / `.BhhBB.` / `BhBBBB` | 四个角各两级台阶，每级 `c` dp：卡片 4、按钮和输入框 3、小标签 2、大面板 5、弹层顶部 6 |
| 底边深一档 | 最下面一行 `b` | 内阴影 `inset 0 -lip`：卡片和按钮 4dp，小部件 2–3dp。按下时收成 1dp，整体下沉 3dp |
| 左上高光 | 第 1 行两颗、第 2 行一颗 `h` | 只放在有颜色的面上（主按钮、警示按钮）：`(2c,c)`、`(3c,c)`、`(c,2c)` 三格，白色 45–50% |

- 凹进去的东西（输入框、开关轨道、计划“纸”、滑块轨道）把深色那一行放在**顶部**（`inset 0 3dp`）。
- 描边（等你确认的卡片）用“外层填描边色、内层缩进 3dp”的两层做法，不用 stroke，这样台阶处不断线。
- **Compose 实现建议**：一个 `PixelCornerShape(step: Dp)`（`GenericShape` 画 20 个点的多边形，草图 CSS 里的 `clip-path` 就是这 20 个点）；底边和高光用 `Modifier.drawWithContent`。封装成 `Modifier.pixelSurface(color, lipColor, step, lip, highlight)`。

## 6. 字体与图标【Claude 定】

- **Silkscreen**（OFL，Regular + Bold，约 60 KB）：时钟、百分比、数量、6 位码这类数字。“%” 用 Nunito，因为 Silkscreen 的 % 缩小后像 z。
- **Nunito**（OFL，可变字重）：英文和数字正文、标题。中文回落到系统字体。
- 等宽：系统 monospace，只用于命令和路径。
- **Logo**：不用字体，手画的像素字 “Critter”，`i` 上的点是小芽的两片嫩芽（#6BCB5F / #3F9442），字下面一格浅阴影。像素行见草图脚本里的 `LETTERS`。
- **像素图标**：所有界面图标是格子画（2dp 一格，跟着文字颜色），和宠物头顶的符号同一套，不用 Material 图标。行数据见草图脚本里的 `ICONS`（看板、设置、返回、目录、分支、终端、VS Code、电脑、网络、提醒、电池、发送、信、扫码、手动输入、锁、悬浮球、专业看板、形象、动画、空状态、种子三态、状态五个符号、月亮）。Android 上建议从同一份行数据生成 `ImageVector`，不手工画 SVG。

## 7. 动效【Claude 定】

**两条规矩**：
1. **小部件按 60 ms 一格跳**（和宠物引擎同一个节拍）：开关圆头 3 格走完 180 ms（`steps(3)`），进度格一格一格填，标签换状态时上跳一格 60 ms，按钮按下/松开 70 ms 一步到位。**大动作用平滑弹簧**：弹层、悬浮球的架子、列表重排。
2. **都有头有尾**：不做无限循环的界面动画（原设计 §9）。持续动的只有宠物。

| 场景 | 做法 | 时长 |
|---|---|---|
| 冷启动首页 | 宠物用 `interactions.appear` 一只接一只钻出来，间隔 80 ms；一天只放一次 | 每只约 1 s |
| 欢迎页 | 五只用 `interactions.join` 钻出来，间隔 260 ms | |
| 按钮 | 下沉 3dp、底边 4→1dp | 70 ms |
| 开关 | 圆头 18dp，`steps(3)` | 180 ms |
| 弹层打开 | 从下滑上，末尾轻微过冲（`cubic-bezier(.18,.9,.28,1.08)` 或 Compose `spring(dampingRatio≈0.8)`）；落稳后宠物“抬头看你” | 300 ms |
| 抬头看你 | App 拼出的片段，五个形象通用：`clips[interactions.notice]` 的小跳，然后 `[lookUp, 12] [blinkPose, 2] [lookUp, 10] [lookCenter, 2]`，再回到原来的动作。【用户定：第一版只播 notice（3 帧）太快看不到】 | 约 1.7 s |
| 弹层关闭 | 直接滑下 | 200 ms |
| 作答成功 | 按钮 3 格变绿、文字换成“✓ 已允许”；宠物切到 done 并播进场（欢呼撒花瓣）；900 ms 后弹层自己关 | |
| 拒绝 | 宠物播 `notice`，弹层直接关 | |
| 发一句 | 像素信沿弧线 7 格飞到宠物头上（每格 60 ms）；宠物 `notice` 后 `petEnd`；下面绿字“已送到” | 约 420 ms |
| 状态变化 | 小头像换代表姿势，标签换色并上跳一格；需要你的卡片平滑挪到最上面（`animateItem`） | |
| 悬浮球展开 | 整个架子从那一堆的高度沿竖直方向长出来（轻微过冲）；宠物自上而下间隔 55 ms 各跳一下（hop） | 240 ms |
| 悬浮球收起 | 宠物自下而上间隔 55 ms 各跳一下，然后架子缩回那一堆的高度，换成那一堆，领头的宠物跳一下落地 | 200 ms |
| 看板打开 / 关掉 | 悬浮球那一堆用 `interactions.vanish` 钻回地里，然后窗口隐藏；看板关掉后窗口出现，用 `interactions.appear` 钻出来 | |
| 看板拖动宠物 | 见 §8.7 | |
| 减少动态效果 | 所有界面过渡退成 150 ms 淡入淡出；宠物停在代表姿势上（现有逻辑） | |

## 8. 各个画面

以草图为准，这里只写结构和规则。

### 8.1 应用图标、启动画面
- 自适应图标（108dp，36×36 格，每格 3dp）：背景层是清晨天空三段加一行抖动、底部草地；前景层是小芽 `base` 姿势，左上角在格子 (9, 13)，脚踩第 23 行。可见区是中间 72dp，小芽 18 格宽落在 66dp 安全区里。
- 单色主题图标：小芽轮廓（含叶子），眼睛挖空。
- 状态栏小图标：12×11 格的同一个轮廓（草图脚本 `SB_ICON`），替换现在的 `stat_notify_sync_noanim` / `stat_notify_more`。
- 启动画面（SplashScreen API）：背景接清晨天空色，图标居中。
- Manifest 加 `android:icon`、`android:roundIcon`。图标用 PNG 还是由格子数据生成 vector 由实现者定。

### 8.2 首次引导与配对
- **新增欢迎页**：清晨草地上五只宠物钻出来，Logo，一句话说明，主按钮「开始配对」，下面一行“要先在 Mac 的 Critter 里打开「手机连接」”。
- 进度：六颗种子（配对、本地网络、通知、悬浮窗、电池优化、后台运行），走过的发芽（绿）、当前的冒花苞（主色）、没到的是种子（灰），旁边写 `n / 6`。
- 每一步：一小块草地插图（宠物用已有姿势：等 Mac 点允许 = 小芽 waiting；通知 = 团子 waiting，头顶是那条通知；保持后台运行 = 啾啾在夜里睡觉）+ 大标题 + 一句说明 + 主按钮 + 跳过 + 跳过的后果。
- 扫码：深色取景，四角像素直角，小芽在框下抬头（`look_up`）。识别成功：取景框闪绿，宠物跳一下。
- 扫码说明按 Mac 上的真实入口写：“在 Mac 上打开 Critter 的「设置…」，打开「允许手机连接」，点「添加手机…」，把出现的二维码放进框里。”
- 等 Mac 点允许：画出 Mac「添加手机」窗口里的那一行（“「手机型号」请求连接”和「拒绝」「允许」），允许按钮用橙色虚线圈出来。
- 手动输入：找到的 Mac 列成卡片（选中的打“已选”标签），8 位码分 4+4 两组格子（和 Mac 上的显示一致）。
- **配对失败按原因分开说**（台账 pair() 那条）：连接层返回原因，界面逐条对应：
  - 码不对或过期（`denied badCode`）：“这个码不对，或者已经过期了。在 Mac 的「添加手机」里点「重新生成」再试。”
  - 在 Mac 上点了拒绝（`denied rejected`）：“Mac 上点了「拒绝」。要配对的话重新扫码，这次点「允许」。”
  - 版本不一致（`denied protocol`）：“这台 Mac 上的 Critter 版本和手机不一致，把两边都更新到最新再试。”
  - 证书对不上（指纹不符）：“这台 Mac 的证书和二维码里的不一样，已经停下。确认扫的是你自己的 Mac。”
  - 没人点允许（等待超时，或 Mac 不发 `denied` 直接关掉）：“Mac 上一直没人点「允许」。回到 Mac 前，重新扫一次码。”
  - 连不上：“连不上这台 Mac。确认手机和电脑在同一个 Wi‑Fi，并且 Mac 上开着「允许手机连接」。”
- 保持后台运行：步骤有先后，所以编号；做完的换对勾、去掉按钮。

### 8.3 首页
- 上部草地 236dp（含状态栏，天空铺到状态栏下面）：左上 Mac 名和连接标签，右上两个图标按钮（看板、设置）。宠物 3dp 一格，地平线在 200dp，脚下白色名字标签；等你确认的那只头顶加橙色气泡“等你确认”。天空按手机时间四档（6–10 清晨、10–17 白天、17–20 黄昏、其余夜里），整点才换；深色模式一直夜里。
- 会话多于 5 个时草地上放最急的 5 个，其余合成一堆（规则沿用桌面的合并逻辑）【Claude 定，细节实现者定】。
- 额度：两张卡，左上名字、右上 Silkscreen 大数字、10 格分段条（< 60% 绿、60–85% 金、≥ 85% 红）、重置时间。
- 会话卡片：左边 56dp 的小草地格子（底色按状态），里面是静止的宠物代表姿势和头顶标记；右边名字 + 状态标签、在做什么、**目录 · 分支 · 来源**（台账：顺序按设计改，用小图标分隔）；底部“上下文”分格条和百分比。
- 等你确认的卡片：橙色 3dp 描边，排第一，多一张命令纸条和「拒绝」「允许」两个按钮（权限请求在列表里直接答；提问和计划是「打开回答」）。
- 离线：天黑、宠物灰着睡、顶部一张“连不上 xxx，正在重试，下面是 n 分钟前的样子”卡片带「重试」；数据变淡，作答按钮变灰并写“连上后才能作答”。
- 空状态：一只睡着的宠物（用户选的形象，没选是小芽），“电脑上还没有会话 / 在电脑上开一个 Claude Code 会话，它的宠物会从这片草地里钻出来。”
- 需要重新配对：沿用现在的处理，按钮换成像素按钮。

### 8.4 悬浮球
- 收起：那一堆（最急的在前，后两只升高 3 格、调暗），上面一个计数标签（状态符号 + 数字），下面“n 个会话”标签，脚下一条浅影子。贴右边时宠物朝左，贴左边朝右。
- 展开：半透明的白色架子（深色时是 surface 94%）贴着屏幕边，顶部计数和“点宠物打开”，每行宠物在外侧、气泡朝内侧（等你确认的气泡是橙色，带“点我回答”），名字 · 来源在宠物下面；底部「收起」。
- 动效见 §7。
- **看板在前台时藏起来**（台账一.2）：看板 `onStart` 时让悬浮球播 vanish 后隐藏，`onStop` 时显示并播 appear。用户自己关着悬浮球时不受影响。

### 8.5 会话详情与「发一句」
- 半透明底部弹层，顶部 150dp 一块草地，宠物 4dp 一格继续它的动作，旁边侧向气泡写在做什么。弹层落稳后宠物“抬头看你”（§7），作答卡片同样。
- 名字 + 状态标签；两列信息（目录、分支、来源、模型、上下文分格条、最后更新），每项一个小图标。
- 「发一句」输入框 + 发送按钮，下面小字说明。发送成功、失败的反馈见 §7。弹层跟着输入法升起。

### 8.6 作答卡片
- 共用外壳：顶部 72×64 的小草地格子（橙底）里是举手的宠物，旁边“名字 + 想做什么”和目录 · 分支 · 来源；底部「电脑上也能答，谁先答算谁的」。
- 权限：命令纸条（深色，等宽，完整显示，最多约 8 行再滚动）；「拒绝并写理由…」文字按钮；「拒绝」（左、次要）「允许」（右、主要、更宽）。
- 提问：每题一个主题小标签 + 问题；选项是小卡片（标题 + 说明），单选圆点、多选方框，选中变淡紫底加描边；「自己写一句…」是虚线卡片；底部「提交 n 个回答」。只有一个单选题时点了就提交（沿用现在的行为）。
- 计划：凹进去的“纸”，可滚动，底部渐隐；「让它改…」「批准计划」。
- 已在电脑上处理：开着花的宠物、“已在电脑上处理”、一句说明、2 秒后自己关。离线、失败的提示放在同一位置。

### 8.7 看板
- **宠物模式**：宠物 6dp 一格（会话多时缩小，沿用现在的排法），地平线 2dp #1A1630，稀疏的暗草；名字、目录 · 分支在地平线下，再下面一条 3dp 的上下文分格条。左上 Silkscreen 时钟和日期，右上 5h / 7d 两条分格额度，再右是模式切换。运行中和等你确认的宠物头上有深色气泡；等你确认的气泡橙色描边，写“想运行 xxx / 点我回答”。
- **拖动一只宠物**（台账一.3）：按下 = `press`；移动超过 3dp = 拎起来（`held`，抬高 3 格），横向跟着手指走（不超出看板），**其他宠物不动**；松手：在当前位置播 `drop` 落地，播完就用 `walkLeft` / `walkRight` 走回自己的位置（引擎现有的跟随行走：一拍 1 格，离家超过 6 格时一拍 2 格），到了眨一下眼。名字标签留在原位当“家”，宠物离家时它的气泡藏起来，回家后再出现。减少动态效果时直接回到原位。轻点仍然是 boop，点等你确认的那只打开作答卡片。【Claude 定：读代码后简化，草图里的“随手指抬高、先下落再走”不做】
- **专业模式**：左栏时钟、日期、两张额度卡（20 格分段条）；右边两列卡片，左上是这只会话的静止宠物（调暗；等你确认的不调暗），等你确认的卡片占两行，带命令纸条和「拒绝」「允许」。
- 防烧屏、低帧率、亮度规则不变。

### 8.8 设置
- 顶部连接卡片高度固定（台账“已配对面板切换有视觉跳动”），状态变化只换文字和图标；「重新配对」「取消配对」两个按钮。
- 分组卡片，每组标题前一个像素图标：形象、悬浮球、看板、提醒、动画与省电。
- 形象：一排小草地格子横向滚动，第一格“跟着电脑”（小电脑图标），然后 Clawd、小芽、团子、啾啾、刺球，每格一只会动的宠物；选中的描主色边、右上角打勾，并播一次 done 的进场。
- 悬浮球大小的分段控件旁边直接显示那个大小的宠物。
- 亮度滑块：10 个小格，滑块头是小太阳。
- 看板被系统拦下时，在看板组里留一条橙色提示和「去打开」（台账“后台启动被拦下时没有提示”）。

### 8.9 通知
- 小图标换成 §8.1 的状态栏图标，颜色用小芽紫。
- 大图标：那个会话的宠物代表姿势，底色按状态（等你确认浅橙、做完了浅绿）。
- 等你确认的请求通知改成 `VISIBILITY_PRIVATE`，公开版本是“<名字> 需要你确认 / 解锁后查看内容”（台账锁屏那条）。
- 看板没能自动打开时发一条低优先级通知“没能自动打开看板”，说明原因，按钮「去设置」。
- 从通知按钮打开卡片被系统拦住时，提示“点通知正文打开”，通知保留。

## 11. 留给实现者的

- 草地视图是一个 View 还是 Compose `Canvas` + 多个 `CritterView`，只要满足省电要求都行。
- 图标资源用 PNG 还是生成 vector。
- 会话很多时首页草地和看板的合并细节。
- 弹簧参数可以按真机手感微调，但节拍规矩（小部件 60 ms 一格）不变。

## 12. 验收

1. 草图里每个画面在真机上都有对应，浅色、深色各过一遍。
2. 台账第一部分三项和 §9 里标了位置的条目逐条对照。
3. 省电：首页不可见时宠物时钟停；没有新增无限循环的动画（代码审查时逐条查）。
4. 减少动态效果打开时，界面过渡都退成淡入淡出。
5. 现有单元测试全部通过；新增的纯逻辑（天空分档、拖动后走回、配对错误分类）有测试。
